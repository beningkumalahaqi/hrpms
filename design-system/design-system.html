05

Usage

Rules for extending the system

Accessibility, responsive behavior, and content conventions that apply whenever a new view is added.

Accessibility

  • Maintain a visible 3px focus ring on every interactive element.
  • Pair status color with text and a meaningful icon.
  • Give icon-only controls an accessible name.
  • Preserve the 44px minimum target for controls.
  • Honor reduced motion by removing transitions and smooth scrolling.
  • Keep table captions, sort state, and validation relationships in the accessibility tree.

Responsive behavior

1280px and up
Four statistic cards, full tables, and the persistent sidebar.
1024px to 1279px
Two statistic cards per row and two-column filter panels.
768px to 1023px
Navigation becomes a drawer; dense tables become record cards.
480px to 767px
Filters stack, page actions become full width, and dialogs use the viewport.
Below 480px
Single-column statistic cards, simplified pagination, and no horizontal page overflow.

Do

  • Use sentence case for headings, labels, buttons, and status text.
  • Format monthly salary as USD with no decimal places.
  • Lead with the consequence in confirmations and validation messages.
  • Reuse the shared classes before adding a new visual variant.

Avoid

  • Adding a second primary button to the same view.
  • Using color without a label to communicate project or budget status.
  • Hiding validation behind a toast or a generic error banner.
  • Introducing modules outside the HR and project administration scope.
